# 项目收官总复习

## 如果只能记住 10 个点

1. 分层不是为了好看，是为了“换东西的时候不用重写整个项目”。
2. FastAPI 的 `Depends` 是依赖注入：Router 说自己要什么，框架负责准备什么。
3. Pydantic Schema 是“给数据立规矩”，漏字段直接 422。
4. SQLModel 表模型管数据库，Schema 管外部契约，两者不要混着用。
5. 密码永远只存 bcrypt 哈希，JWT 只做无状态身份凭证。
6. RAG = 先检索再生成，目的是让 AI 的回答有依据、有出处。
7. 流式输出 = 后端逐块返回，前端逐字显示，体验像打字机。
8. 长任务不能塞在 HTTP 请求里，要入队 + Worker 执行 + 轮询状态。
9. 部署和开发环境的区别要交给环境变量，代码里不写死密钥。
10. GitHub Pages 是子路径部署，Vue Router 必须设置 `base`，否则路由空白。

## FastAPI 高频追问

### 为什么用 FastAPI？

异步原生、Pydantic 校验、自动生成 `/docs`、依赖注入清晰。
对 Agent 项目很关键：流式响应和异步任务都是异步场景。

### Pydantic 和 SQLModel 的区别？

- Pydantic：校验“外界进来的数据和返回出去的数据”。
- SQLModel：把数据库表映射成 Python 对象。

面试可以这么说：

> Pydantic 管“接口契约”，SQLModel 管“存储结构”。它们可能字段长得像，但职责不同。
> 如果直接拿 Model 返回，容易把数据库内部字段泄露出去；用 Schema 隔离更安全。

### 422 是什么？

FastAPI 用 Pydantic 校验请求体失败时返回 422 Unprocessable Entity。
比如 `BlogPostCreate` 要求 `title`，漏掉后就会 422。

### Depends 到底做了什么？

依赖注入不是魔法，是“把准备工作的职责交给框架”。
`get_session` 每次请求创建一个数据库会话，请求结束自动关闭；
`get_current_user` 每次验证 JWT 并返回用户。

## RAG 必背流程图

```text
knowledge/*.md
  → 按长度切块（500 字，重叠 50 字）
  → jieba 中文分词
  → 建倒排索引：词 → [(chunk_id, count)]
  → 用户提问
  → 对查询分词，按词频打分
  → 返回 Top-K 资料块
  → 拼进 system prompt
  → LLM 生成回答 + 返回出处
```

面试要点：

- 为什么要切块：整篇塞进去会超上下文、增加成本、容易被无关内容干扰。
- 为什么要有重叠：避免一句话被从中间切开，语义断裂。
- 为什么返回出处：让回答可追溯，也降低“编造”的风险。
- 现在的版本是词法检索，升级方向是 embedding 向量检索、混合检索、重排序。

## Agent 最小循环

```text
感知用户消息
  → 调用工具（RAG 检索）
  → 组织上下文（资料 + 历史 + 问题）
  → 大模型输出
  → 返回答案和出处
```

这个循环就是 Agent 的“最小闭环”。面试时不要一上来讲多 Agent，
先把单 Agent 闭环讲清楚，再讲“为什么以后可以拆多 Agent”。

## 异步任务必背

为什么不能直接同步跑摘要？

> AI 任务可能跑几十秒，HTTP 请求不能一直占着。
> 正确做法是把任务写进数据库，状态设为 PENDING，由后台 Worker 轮询执行，
> 前端拿到 task_id 后轮询状态。

当前实现：

```text
POST /api/tasks/summarize
  → Task 表新增 PENDING
  → asyncio Worker 每 0.5 秒扫一次 PENDING
  → 执行注册好的 handler
  → 更新 SUCCEEDED / FAILED
  → GET /api/tasks/{id} 查状态
```

升级方向：Redis Stream、Celery、多 Worker、心跳、死信队列、重试。

## 部署必背

```text
前端：GitHub Actions 构建 → GitHub Pages
后端：Render Web Service → uvicorn
数据库：Neon PostgreSQL → DATABASE_URL
密钥：Render 环境变量，不写进代码
```

踩坑记录：

- Render 第一次启动失败：项目里没有 `backend/`，start command 不对。
- 数据库认证失败：`DATABASE_URL` 填错或密码不一致。
- 根路径返回 404：后端只提供 `/api`，访问 `/` 当然找不到路由。
- GitHub Pages 首页空白：Vue Router 没设置 `base`，路由匹配不到子路径。

## 前端必背

- `ref`：响应式变量，`ref<Post[]>([])` 表示装着文章数组的响应式盒子。
- `computed`：根据已有响应式数据自动计算，比如分类筛选、文章统计。
- `axios`：HTTP 客户端，`axios.get<Post[]>` 表示 data 是 Post 数组。
- `router-link`：Vue 的声明式跳转。
- `createWebHistory(import.meta.env.BASE_URL)`：适配 GitHub Pages 子路径。
- 乐高设计系统：颜色变量、硬阴影、粗描边、凸点，用 CSS 变量统一管理。

## 最后的叙事模板

面试不是背代码，而是讲“我遇到了什么问题 → 怎么拆解 → 做了什么 → 结果怎样”。

```text
问题：AI 回答没有依据，用户不信。
拆解：先检索 → 再生成。
实现：knowledge/ 切块 → 分词 → 倒排索引 → Top-K → 拼 prompt。
结果：回答带出处，体验完整；后续还能升级 embedding 和混合检索。
```

把每一个模块都用这个模板讲一遍，面试就会显得非常扎实。
