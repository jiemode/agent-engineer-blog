# AnonForge 项目理解地图

AnonForge 不是一个 Demo，而是一个能跑起来的“小说 → 剧本 → 资产 → 分镜 → 媒体”全流程 AI 创作平台。它的价值不是某一个炫技模块，而是**把 AI 能力嵌进一条真实的业务流水线**。

## 推荐阅读顺序

1. [00-从git历史看懂项目的诞生](./00-从git历史看懂项目的诞生)  
   先用提交历史还原“项目是怎么一步步长出来的”。
2. [01-项目全貌与架构地图](./01-项目全貌与架构地图)  
   建立全局坐标系，之后所有模块都往这个地图里放。
3. [02-后端启动与基础设施](./02-后端启动与基础设施)  
   理解 FastAPI 应用是怎么组装起来的：配置、数据库、路由、鉴权、中间件。
4. [03-用户鉴权与前端会话](./03-用户鉴权与前端会话)  
   看一次完整的“登录 → 带 Token 请求 → 过期自动续期”闭环。
5. [04-模型网关与Provider可插拔设计](./04-模型网关与Provider可插拔设计)  
   这是全项目最值得背下来的一段架构：多模型供应商抽象。
6. [05-通用异步任务引擎](./05-通用异步任务引擎)  
   AI 任务不能同步等，它如何用 Redis Stream + 数据库实现可靠任务系统。
7. [06-RAG系统与混合检索](./06-RAG系统与混合检索)  
   从小说章节到可检索知识库，向量、词法、规则检索如何融合。
8. [07-Harness-Agent底座与多Agent创作](./07-Harness-Agent底座与多Agent创作)  
   Agent 不是一把梭，而是有边界、有工具、有记忆、可替换运行时。
9. [08-剧本创作工作流状态机](./08-剧本创作工作流状态机)  
   把 Agent 对话升级成“配置 → 三阶段创作 → 质量校验 → 自修复”状态机。
10. [09-数据资产与提示词工程](./09-数据资产与提示词工程)  
   提示词、技能、艺术风格库如何像数据一样被组织。
11. [10-工程化测试与安全规范](./10-工程化测试与安全规范)  
   一个工业级项目在代码之外还要守住哪些底线。
12. [11-面试怎么讲AnonForge](./11-面试怎么讲AnonForge)  
   把理解翻译成面试语言：讲法、话术、高频追问。

## 一句话记忆

> 前端是工作台，后端是流水线，Provider 是插座，任务引擎是传送带，RAG 是资料库，Agent 是工人，Skill 是工人手册，数据/媒体是产品。
