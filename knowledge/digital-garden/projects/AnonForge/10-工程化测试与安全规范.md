# 工程化测试与安全规范

## AGENTS.md：把开发规范写进仓库

`backend/AGENTS.md` 定义了：

```
模块组织：不要乱加顶层目录
命令：docker compose 优先，python -m compileall 做语法检查
风格：PEP 8、snake_case、类型标注、不写裸 except
测试：行为变化必须加测试，修复缺陷优先补回归测试
提交：Conventional Commits，PR 说明影响范围与回滚方式
Agent 执行规范：最小改动、如实报告验证结果、禁止伪造测试
```

面试里提到“我把开发规范写进 AGENTS.md”，说明你有工程治理意识。

## 测试体系

```
backend/app/tests/
  base.py             EnvTestBase（环境变量注入）/ ApiTestBase（TestClient）
  test_health.py      健康检查
  test_config.py      配置解析
  test_database.py    数据库
  test_user_*.py      用户模型/路由/服务
  test_novel_*.py     小说爬取、解析、代理
  test_asset_service.py
  test_provider_runtime.py
  ...
```

测试基类很朴素但实用：

```python
class ApiTestBase:
    def create_client(self):
        return TestClient(create_app())
```

测试文件镜像源码结构，函数名描述行为：

```
test_login_rejects_invalid_password
test_start_browser_proxy_process_uses_current_python
```

## run.py：开发体验也是工程

```python
def main():
    browser_proxy_process = start_browser_proxy_process()  # 自动拉起爬虫代理
    uvicorn.run("app.main:app", ..., loop="none")
```

检测端口已占用就不重复启动，退出时优雅停掉。这种“帮你管好周边进程”的小设计很加分。

## Docker Compose：基础设施即代码

```yaml
postgres:  image + 环境变量 + 数据卷 + healthcheck(pg_isready)
redis:     image + appendonly + healthcheck(redis-cli ping)
```

healthcheck 保证依赖真正可用，而不是“容器起来了就当作可用”。

## 安全底线（真实教训）

`.claude/verification-report.md` 是项目自己的审查报告，暴露过三个 P0：

```
P0-1 云凭据硬编码进 config 默认值并提交 git → 必须吊销密钥 + 清历史
P0-2 大重构删了模型但没删旧服务，pytest 收集直接 ImportError
P0-3 470MB 生成图片提交进 git，.gitignore 没覆盖 data/media
```

这三条是极好的面试素材：

```
密钥不进 git / 敏感字段加密 / .env 管理
测试是红线：改动前必须本地验证
二进制资产不进版本库 / gitignore 要覆盖运行时数据
```
