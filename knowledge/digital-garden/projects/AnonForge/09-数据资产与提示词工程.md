# 数据资产与提示词工程

## data/ 目录是第二个代码库

```
data/
├── models/       bge-small-zh-v1.5 本地 embedding 模型
├── chroma/       RAG 向量库持久化
├── skills/       提示词与技能资产
│   ├── screenwriting/   四个创作阶段 Agent
│   ├── events/          章节事件提取
│   ├── art_list/        数十种艺术风格包
│   ├── director_manual/ 分题材导演手册
│   └── *.md             通用技能（harness、资产、分镜）
├── script/
│   ├── tools/            Agent 工具定义（Markdown 即契约）
│   └── *_runtime_contract.md  运行时契约
└── browser/      爬虫浏览器用户数据
```

## Skill 的通用结构

一个 Skill 就是一份 Markdown，但结构非常工程化：

```
角色定位   你是谁、只干什么
输入       你拿到什么
工作方法   具体怎么做
输出格式   严格到表格结构、Markdown 标题、禁止项
```

例如剧本生成助理：

```
每集标题可解析：# 项目名 EP01：单集标题
场次编号：1-1 场景地点 日/外
动作行：△动作描写
对白：角色名（动作，情绪）：台词
禁止：裸对白、说明书旁白、漏集
```

这不是“写一段好提示词”，而是**把提示词当协议**：输出格式可解析，后续质量校验才能自动化。

## 运行时契约：Agent 的行为边界

```
guide_runtime_contract.md  引导助理契约
stage_runtime_contract.md  阶段助理契约
```

契约里写着：

```
- 创作配置由用户确认锁定，助理只读不写
- 禁止凭记忆编造章节事件
- 只输出可直接写入工作区的 Markdown 正文
- 不要输出工具调用说明、执行日志、隐藏推理
```

这正是 Agent 工程里的“系统提示词之外的第二层约束”。

## 工具文档即代码

`data/script/tools/get_rag_context.md`：

```
用途    读取本轮 RAG 检索上下文
参数    无
返回    text / runtime / hits
使用时机  资料不足时必须调用，禁止凭记忆作答
```

前端/后端都不需要单独维护工具 schema，Markdown 是唯一事实源，再在代码里组装成真实工具函数。

## 艺术风格库：从提示词到产品

```
data/skills/art_list/
  2D_cel_animation/
    README.md
    images/character_turnaround_sheet.png
    images/landscape_four_states_sheet.png
    images/scene_character_in_landscape.png
```

每种风格不仅给描述，还带统一的三视图参考图，用于生图时保持风格一致性。另有：

```
STYLE_TAXONOMY.md     风格分类法
SAFETY_NAMING_GUIDE.md 命名安全规范
```

`director_manual/` 按题材（甜宠、仙侠、悬疑……）组织导演手册，把“行业知识”变成可检索的 RAG 资料。

## 资产与媒体流水线

```
剧本分集
  → 资产抽取（LLM：角色/势力/道具/场景）
  → 资产补全（autocomplete）
  → 图像提示词合成（asset_image_prompt skill）
  → 媒体中枢生成图片/视频（scope_type=asset）
  → 封面回写 / 父子资产绑定
```

`MediaAsset` 是统一媒体中枢：

```
type      image / video / audio
role      final（封面）/ generated / reference
status    pending → processing → ready / failed
scope     挂在哪个业务对象上（asset/episode...）
```

为什么统一？因为“上传一张图”和“AI 生成一段视频”最终都要：落盘、给 URL、可回写、可追溯。

## 面试怎么答“提示词工程”

> “我们不是把提示词写在代码字符串里，而是把 Skill、工具契约、风格库、导演手册都做成数据资产：Agent 角色有标准 Markdown 结构，输出格式可解析，质量校验可自动化；艺术风格带参考图和分类法，导演知识按题材组织后进入 RAG。改提示词不需要改代码，加风格只是加一个数据包。”

这就是“提示词工程工业化”的答案。
