# 面试怎么讲 AnonForge

## 30 秒版本（自我介绍 / 项目开场）

> “AnonForge 是一个 AI 短剧创作平台：导入小说后，系统自动清洗章节事件、建立 RAG 知识库，再通过多 Agent 完成故事骨架、改编策略和剧本生成，最后产出角色资产、分镜和视频素材。我负责后端架构与 AI 链路设计，包括模型供应商网关、通用异步任务引擎、RAG 混合检索和 Agent 工作流。”

## 2 分钟版本（架构叙事）

按这个顺序讲，不要跳：

```
1. 业务闭环：小说 → 事件 → RAG → Agent → 剧本 → 资产 → 分镜 → 媒体
2. 分层：FastAPI 路由 → Service → 基础设施（PG/Redis/Chroma/Provider）
3. 同步链路：聊天/创作走 NDJSON 流式
4. 异步链路：长任务走任务引擎
5. 两个亮点：Provider 可插拔 + 通用任务引擎
6. 一个质量闭环：规则校验 + 自修复
```

## 5 分钟版本（选一个深度主题）

面试官追问时，任选一篇笔记展开：

```
Provider 抽象 → 契约/配置即代码/工厂/网关
任务引擎     → Job/Item/DeadLetter、Redis Stream、CAS、心跳、Scavenger
RAG         → 事件结构化、本地 embedding、混合检索、意图解析
Agent       → Harness 边界、运行时协议、工具、记忆隔离、CrewAI
状态机      → 配置确认、阶段前置、逐集生成、回滚确认
```

## 高频问题与答题要点

### “为什么用 FastAPI？”

> “异步原生、依赖注入完善、Pydantic 校验，和我们的异步任务/流式协议契合。Windows 下我们还处理了事件循环兼容问题。”

### “异步任务为什么不自研，用 Celery 不好吗？”

> 见 05 篇：任务与业务表强一致、形态简单、CAS + 心跳 + PEL 自愈。成熟方案是另一种权衡。

### “RAG 检索结果不好怎么办？”

> “我们不是单一向量检索：意图解析决定走章节区间、字段元数据、词法还是视觉技能库；分块带重叠、内容 hash 增量更新；还提供 runtime 诊断让每次检索可观测。”

### “多 Agent 一定比单 Agent 好吗？”

> “不一定。我们是先单 Agent 跑通，再按阶段拆 Agent，最后才用 CrewAI 团队。Agent 拆分的收益来自职责和提示词聚焦，代价是编排和流式复杂度。”

### “大模型幻觉怎么控制？”

> “三层：数据层先做结构化事件，RAG 注入事实；约束层运行时契约禁止编造，工具强制读取；输出层规则质量校验 + 自修复，不合格不落库。”

### “项目里最难的 Bug？”

> 可以用 `.claude/context-summary-novel-crawl-card2-bug.md`：同一本小说多条卡片共用 dirid 导致选中错误、缓存短路、Vue key 冲突。复盘过程展示了“现象 → 根因 → 修复 → 测试”的完整 Debug 思维。

## 诚实原则

如果这是学习项目，不要包装成商业项目。更好的说法：

> “这是我和 AI 协作、按工业级标准从 0 到 1 做的项目，我有完整 git 历史、测试和审查报告。我讲它的每一步都基于真实提交。”

面试官真正在意的不是“你做过生产环境”，而是：**你有没有真实做过复杂系统的完整链路，并且能说清每个决策**。
