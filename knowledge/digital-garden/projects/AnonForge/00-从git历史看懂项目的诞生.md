# 从 git 历史看懂项目的诞生

很多人在读大项目时直接看代码，结果被 20 万行淹没。正确姿势是**先看 git log**，因为提交历史就是作者当时的心智顺序。

## 从时间线能读出 5 条规律

### 1. 先做“壳”，再塞“AI”

项目初始化时根本没有 Agent。先有：

```
用户系统 → 项目系统 → 风格系统 → 模型配置 → 小说系统
```

AI 能力是在**业务底座已经能跑**之后才加的。这是工业项目最真实的顺序：AI 是业务的一个环节，不是项目的全部。

### 2. 异步化要趁早

初始化当天就做异步重构。原因是 Psycopg 的异步连接在 Windows 默认事件循环下不兼容，而且异步化会影响后面所有模块。**技术债越晚还越贵**。

### 3. 先有数据，再有检索

RAG 之前先有小说爬取和章节事件清洗。没有“结构化数据”，RAG 就没有素材。顺序是：

```
爬小说 → 清洗章节事件 → 向量化 → 检索 → Agent 使用
```

### 4. Agent 底座先抽象，再上多 Agent

先做 `Harness Agent`（有边界的单 Agent），再做 RAG，再做三阶段创作，最后才切到 CrewAI 团队模式。**先证明单 Agent 能跑通，再考虑协作**。

### 5. 每个 Commit 都有明确动词

`feature/refactor/fix` 前缀 + 具体业务。大厂面试官很吃这一套：它证明你写代码有“变更意识”，而不是一次性堆一座山。

## 面试怎么用

面试官问“这个项目怎么从 0 到 1 的”，不要背架构，要讲顺序和原因：

> “我先搭了前后端和 docker 底座，立刻把数据库层异步化；然后完成用户鉴权和项目管理，把业务闭环跑通；接着接入小说爬取与事件清洗，产生真实数据；有了数据才做 RAG；再在 RAG 之上设计 Harness Agent，最后才是多 Agent 团队和媒体生成。每一步的依赖都很清楚：先有数据，再有检索；先有单 Agent，再有多 Agent。”

这就是 git 历史给你的“项目叙事权”。
