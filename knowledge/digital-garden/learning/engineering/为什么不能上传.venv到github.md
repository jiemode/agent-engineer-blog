# 很多人都说

> "不要上传 `.venv`"

但是不会告诉你为什么。

原因其实很简单

`.venv` 里面是什么？

Windows 用户：

```
Scripts/
python.exe
```

Mac 用户：

```
bin/python
```

Linux 用户：

```
bin/python
```

甚至：

CPU 架构都可能不同。

所以：

**`.venv` 是机器相关的。**

而：

`pyproject.toml`

是：

**项目相关的。**

所以 GitHub 永远保存的是：

> **"如何构建环境"**

而不是：

> **"已经构建好的环境"**

这就是现代软件工程的思想

## `.venv`

负责：

> **"这里面装了什么？"**

里面是真正的 Python。

真正的 FastAPI。

真正的 Uvicorn。

真正的 Pydantic。

可以理解成：

> **厨房。**

所有食材都在里面。

---

## `pyproject.toml`

负责：

> **"厨房应该有什么？"**

它不是食材而是**菜单**

例如：

```
dependencies = [
    "fastapi",
    "uvicorn",
]
```

意思就是：

> 这个项目需要 FastAPI 和 Uvicorn。

---

所以真正的流程其实是：

```
pyproject.toml
        │
        ▼
uv sync
        │
        ▼
.venv
```

这就是为什么不会把：

```
.venv
```

上传 GitHub。

但是：

一定会上传：

```
pyproject.toml
```

因为别人拿到菜单执行：

```
uv sync
```

厨房就自动建好了
