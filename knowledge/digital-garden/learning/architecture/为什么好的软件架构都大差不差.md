# ⭐原因一： 一个模块，只负责一件事情。

> **Single Responsibility Principle**

单一职责原则

# 什么叫单一职责？

举一个最简单的例子

汽车是不是：
```
发动机

负责：

提供动力
```

轮胎：

```
负责：

跑
```

方向盘：

```
负责：

转向
```

刹车：

```
负责：

停车
```

如果方向盘还能：

```
发电

制冷

放音乐

导航
```

......

保养一次得拆半辆车，同理，软件也一样，于是：

```
Router

↓

只负责HTTP
```

---

```
Service

↓

只负责业务流程
```

---

```
Repository

↓

只负责数据库
```

---

```
Agent

↓

只负责思考
```

---

```
Tool

↓

只负责调用工具
```

# 这就是为什么 Github 的agnet项目都长这样

以前是不是一直很好奇为什么所有项目起手都是：

```
routers/

services/

repositories/

models/

schemas/

config/
```

现在答案来了，是作者在遵守：

> **单一职责原则。**

例子：
```
app/

│

├── routers/
│
│     chat.py
│     auth.py
│     workflow.py
│
│
├── services/
│
│     chat_service.py
│     auth_service.py
│
│
├── agents/
│
│     chat_agent.py
│
│
├── repositories/
│
│     user_repository.py
│
│
├── models/
│
├── schemas/
│
├── config/
│
├── core/
│
└── main.py
```

# 实际上整个backend真正只有三层

很多目录都是这三层拆出来的。

---

# 第一层

## Interface Layer（接口层）

里面就是：
```
routers/
```

职责：

> **和外界交流。**

例如：

HTTP，WebSocket，Webhook，CLI。

以后MCP Server其实也属于这一层。

MCP虽然不是HTTP但是它也是**别人调用你的入口。**

---

# 第二层

## Business Layer（业务层）

就是：

```
services/

agents/
```

这里才是真正干活的地方，业务逻辑之所在

例如：

```
ResumeService

↓

AI分析简历

↓

返回建议
```

---

# 第三层

## Infrastructure Layer（基础设施层）

这里包括：

```
Repository

Database

Redis

OpenAI

Claude

S3

OSS

Milvus

Qdrant

Kafka
```

基建，外部工具

---

# 一张真正的软件架构图。

```
             用户

               │

               ▼

       Interface Layer
      (Router / API)

               │

               ▼

       Business Layer
   (Service / Agent)

               │

               ▼

   Infrastructure Layer

Database   Redis   OpenAI
```

# 那为什么还有：

```
schemas/

models/

config/
```

他们是公共模块

例如：

Schema

```
ChatRequest

ChatResponse
```

Router用，Service也用，所以它不能放Router也不能放Service。

于是单独：

```
schemas/
```

---

Config同理也是

```
OPENAI_API_KEY

DATABASE_URL
```

所有地方都可能用

所以放：

```
config/
```

---

Models也是，

数据库模型，Repository用Service也可能引用

于是单独：

```
models/
```
